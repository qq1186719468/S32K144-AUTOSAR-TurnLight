# 转向灯工程底软配置审计

工程根目录：`G:/S32K144_Start_TurnLight_IAR_20260912/S32K144_Start_new_IAR`

## 1. 配置文件入口

EB tresos ECUC 配置位于 `Config/ECUC/`，重点文件：`S32K144_Start_Mcu_ecuc.arxml`、`..._Port_ecuc.arxml`、`..._Dio_ecuc.arxml`、`..._Spi_ecuc.arxml`、`..._Can_ecuc.arxml`、`..._CanIf_ecuc.arxml`、`..._PduR_ecuc.arxml`、`..._Com_ecuc.arxml`、`..._Rte_ecuc.arxml`、`..._Os_ecuc.arxml`。生成后的 C/H 可在 `Appl/GenData` 和 `MCAL/*/generate_P{B,C}` 对照。

## 2. 与转向灯直接相关的 MCAL 配置

### Mcu/时钟

`S32K144_Start_Mcu_ecuc.arxml`：RUN 模式系统时钟使用 SPLL，`McuSystemClockFrequency=80000000` Hz，内核分频 2、总线分频 2（40 MHz bus）、Flash 20 MHz；SPLL 输入 SOSC 8 MHz、乘数 40，输出 160 MHz 后分频到 80 MHz。CAN 时钟参考点 `McuClockReferencePoint_CAN=80000000`、选择 `RUN_SYS_CLK`；SBC SPI 参考点 4 MHz（SIRC DIV2），LPSPI1 参考点 4 MHz（SOSC DIV2）。LPSPI1 外设时钟来自 SPLL，40 MHz。注意 XML 中还保留了 FIRC 48 MHz 的时钟配置容器，实际 RUN 选择由 `McuRunClockConfig/McuSystemClockSwitch=SPLL` 确定。

### Port

`S32K144_Start_Port_ecuc.arxml`：

* CAN0：PTE4=`CAN0_RX`，PTE5=`CAN0_TX`，PCR 132/133。
* SBC SPI：PTB14=`LPSPI1_SCK`、PTB15=`LPSPI1_SIN`、PTB16=`LPSPI1_SOUT`、PTB17=`LPSPI1_PCS3`，PCR 46~49。
* 灯 GPIO：PTD0、PTD1、PTD15、PTD16，均 GPIO 输出；启动电平 HIGH（LED 低有效，所以初始熄灭）。Port 还启用运行时 `Port_SetPinDirection` 与 `Port_SetPinMode` API。

### Dio

`S32K144_Start_Dio_ecuc.arxml`：DioPort_0 的端口 ID 3（PORTD）；DioChannel_PTD0=0、PTD1=1、PTD15=15、PTD16=16。生成代码可从 `Appl/GenData/src/Dio_Cfg.c`、`MCAL/Dio_TS.../generate_PC/src/Dio_Cfg.c` 查看。应用通过 DIO channel 写低电平点灯、高电平灭灯。

### Spi/LPSPI

`S32K144_Start_Spi_ecuc.arxml`：SBC 读通道 `SpiChannel_SBC_Read`，ID 0、8 bit、EB buffer、最大长度 4；Job 0、同步；Sequence `SpiSequence_0_SBC` ID 0。外部设备 `SpiExternalDevice_SBC` 使用硬件 CS `PCS3`、低有效、MSB first、100 kbit/s、连续 CS、主机模式；硬件单元 `CSIB0`（对应 LPSPI1）。SPI 通用配置启用 cancel/HW status，DMA 关闭。

## 3. CAN 接收/发送链路

### Can MCAL

`S32K144_Start_Can_ecuc.arxml`：仅 CAN controller 0，`FlexCAN_0`，激活；中断接收/发送/BusOff；Basic CAN，标准 ID，最大 DLC 8。波特率配置 500 kbit/s：时钟 80 MHz、Prescaler 8、PropSeg 7、Seg1 6、Seg2 6、SJW 1，单采样。RX Basic object CAN ID 0（硬件过滤关闭，软件筛选），TX object ID 0。

### CanIf

`S32K144_Start_CanIf_ecuc.arxml`：CAN0 共用 HRH/HTH。应用 RX PDU `msg_Receive_oCAN00_76f25845_Rx`：标准 ID 528（0x210）、DLC 8、Rx PduId 2、上送 `PduR_CanIfRxIndication`；应用 TX PDU `msg_Transmit_oCAN00_29db34a4_Tx`：标准 ID 512（0x200）、DLC 2、Tx PduId 2、确认回调 `PduR_CanIfTxConfirmation`。另有诊断 0x610/0x612 和旧测试 PDU。

### Com/PduR

`S32K144_Start_Com_ecuc.arxml` 中，0x210 接收 PDU handle 0，DEFERRED 处理，信号映射：CrashIntensity bit3/1、EmergencyBrakeLight bit4/1、VehicleSpeed_Valid bit5/1、HazardSw bit8 size4、IGN_Status bit12 size4、TurnLampFb_FL bit16 size4、FR bit20、RL bit24、RR bit28、TurnLampSw bit32 size4、VehicleSpeed bit40 size8。0x200 发送 PDU handle 1，包含左状态 `LA_St_DirectionLampL` bit1 size4、右状态 `LA_St_DirectionLampR` bit8 size4 及其他灯计数信号；TransferProperty=PENDING，周期发送由 Com Tx mode 配置。

PduR 的应用接收源是 CanIf→Com，应用发送路由是 Com→CanIf；配置文件 `S32K144_Start_PduR_ecuc.arxml`，生成路由在 `Appl/GenData/PduR_{L,P}cfg.*`。

## 4. OS/RTE 调度

`S32K144_Start_Rte_ecuc.arxml`、`..._Os_ecuc.arxml`：OS 有 `OsTask_BSW_SCHM`（优先级 10，非抢占，1024 B，共享栈）和 `OsTask_APP`（优先级 15）。BSW 10 ms 事件中按位置运行 CanSM、CanTp、BswM、Com Rx/Tx、Dcm、EcuM 等；应用 `TMT_TurnLight_Runnable_10ms` 与 `TMT_TurnLightArb_Runnable_10ms` 映射到 BSW 10 ms 事件。`CtLedTask` 和 SBC 测试 Runnable 在 APP 任务。生成 RTE 调度可从 `Appl/GenData/Rte_Cfg.h` 和 `Rte.c`/`SchM` 查找。

## 5. 面试/学习路径

1. 先从板级目标反推：LED2/3/4/5 对应 PTD0/1/15/16，J3 对应 CAN0 PTE4/5，SBC SPI 对应 PTB14~17；解释 Port→Dio/Spi/Can 的硬件落点。
2. 在 EB tresos 依次打开 Mcu、Port、Dio、Spi、Can、CanIf、Com、PduR、Os/Rte。每次只回答“输入/输出、ID、周期、硬件资源、生成代码位置”。
3. 以 0x210 左转帧为主线：CAN controller 0 ISR → CanIf Rx PDU 528 → PduR → Com 解包 bit32 TurnLampSw=1/bit12 IGN=2 → RTE `TurnLight_Runnable_10ms` → Stateflow → Arb → IoHwAb/Dio 写 PTD0/15；状态反馈再由 Com 组 0x200（bit1/bit8）。
4. 实验修改优先改 ECUC 后重新 Generate，再编译烧录。只为定位问题时可临时改生成 C，并记录“生成文件会被覆盖”。
5. 面试常问参数：CAN 500 kbps 的时钟与位时序、标准 ID 和 Basic CAN、RX/TX PDU ID、Com bit position/size/endian、Port PCR 多路复用、Dio 低有效、SPI CS/CPOL/CPHA/baud、OS 10 ms 映射。

## 6. 代码核对点

### 6.1 配置与生成代码的时间一致性

复核时发现 `Config/ECUC/S32K144_Start_Mcu_ecuc.arxml` 的时间戳为 2024-08-10，而 `Appl/GenData/src/Mcu_PBcfg.c` 的时间戳为 2021-06-10；该生成 C 中仍可见 `SCG_SPLLCFG_MULT_U32(24U)`，与当前 ECUC 中的 SPLL 乘数 40 不一致。因此不能只根据旧的 `Mcu_PBcfg.c` 反推当前 ECUC 的时钟树。

学习和面试时的证据优先级为：

1. EB tresos 当前打开的 ECUC 参数；
2. 最近一次 Generate 的日志和生成文件时间；
3. 当前实际烧录镜像对应的 `Can_Lcfg.c`、IAR 运行观察值或示波器/CAN 分析仪测量结果。

在修改底软配置前，应先在 EB tresos 中重新 Generate，再执行 IAR Rebuild，并记录生成时间和编译日志。重新生成前，可以把旧生成文件当作“当前可运行镜像的历史证据”，不能当作当前 ECUC 的唯一依据。

* `Appl/GenData/src/Port_PBcfg.c`、`Dio_Cfg.c`、`Mcu_PBcfg.c`、`Spi_PBcfg.c`、`Can_PBcfg.c` 是生成配置落地。
* `Appl/GenData/CanIf_PBcfg.c`、`Com_PBcfg.c`、`PduR_PBcfg.c` 是通信映射落地。
* 右侧 0x200 状态历史上存在生成应用层 `TurnLightAct.c` 汇总映射错误（右状态误读 RL），此问题属于 SWC 代码而非 MCAL 参数，排查 CAN 状态异常时应区分。

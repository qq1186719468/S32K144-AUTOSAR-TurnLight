# 转向灯底软学习：课件需求到 DaVinci 配置

## 1. 课件和当前教学工程的边界

课件目录：`D:\BaiduNetdiskDownload\lesson\BCM实战\转向灯\课件`

课件给出了产品需求、服务参数和 RTE 接口，但没有 DaVinci Configurator 的操作截图。因此，配置界面步骤需要结合当前工程的 ARXML、生成代码和 IAR 工程反推。

课件是完整产品规格；当前 S32K144 教学板工程是简化实现：CAN `0x210` 模拟部分开关、点火和反馈输入，四路 LED 代替实车 HSD 输出。不能把课件中的 AD、GPIO 故障采样、EEPROM 配置和完整 DTC 诊断都当成已经在板上实现。

## 2. 总体配置链路

```text
课件需求
  -> Developer：DataType、PortInterface、SWC、Runnable、Composition
  -> SystemExtract/Communication
  -> Configurator：Mcu、Port、Dio、Can、CanIf、PduR、Com、Os、Rte、Spi

  -> IoHwAb/启动代码适配
  -> IAR 编译下载
  -> TSMaster、IAR、示波器验证
```

## 3. Developer：当前工程实际做了什么

### 3.1 数据类型和接口

`Config\Developer\DataTypes.arxml` 定义 `uint8`、转向位置枚举和 `TurnLightService` 结构。课件中的服务字段是：

```text
TurnLightPosition、TurnLightOnOff、TurnLightDutyCycle、TurnLightCycle、
TurnLightTimes、TurnLightNumber、TurnLightPriority
```

`Config\Developer\PortInterfaces.arxml` 定义 Sender-Receiver 数据接口和 Client-Server 服务接口。

### 3.2 三个 SWC

| SWC | 读取/调用 | 写出/提供 | Runnable |
|---|---|---|---|
| TurnLight | 开关、IGN、Hazard、碰撞、紧急制动、车速、反馈、计数；调用 TurnLightService | TurnLampSwMode | `TurnLight_Runnable_10ms` |
| TurnLightArb | 接收 TurnLightService | FL/FR/RL/RR 仲裁模式；提供服务 | `TurnLightArb_Runnable_10ms`、服务 Operation |
| TurnLightAct | 读取四路仲裁模式 | 四路 CtrlCmd、左右计数、左右 CAN 状态；调用 IoHwAb | `TurnLightAct_Runnable_10ms` |

对应文件：

```text
Config\Developer\ComponentTypes\TurnLight.arxml
Config\Developer\ComponentTypes\TurnLightArb.arxml
Config\Developer\ComponentTypes\TurnLightAct.arxml
Config\Developer\ECUProjects\S32K144_Start.arxml
```

### 3.3 Composition 连接

```text
TurnLight --TurnLightService--> TurnLightArb
TurnLightArb --四路 Out--> TurnLightAct
TurnLightAct --IoHwAb Operation--> Cdd_IoHwAb
Cdd_IoHwAb --Dio--> PTD0/PTD1/PTD15/PTD16
```

Developer 阶段解决“软件组件之间谁连接谁”；它不负责 CAN 波特率、PORT PCR 或 MCU 时钟。

## 4. Configurator：按实际工程学习

### 4.1 Mcu

工程文件：`Config\ECUC\S32K144_Start_Mcu_ecuc.arxml`

重点查看 `McuModuleConfiguration` 和 `McuClockSettingConfig_0`：

```text
SOSC = 8 MHz
RUN Core/System = 80 MHz
RUN Bus = 40 MHz
Flash = 20 MHz
CAN reference = 80 MHz
LPSPI1 peripheral clock = 40 MHz
LPSPI1 reference point = 4 MHz（需确认 SPI 驱动实际引用）
```

启动代码在 `Appl\Source\EcuM_Callout_Stubs.c` 中依次调用：

```c
Mcu_Init(&McuModuleConfiguration);
Mcu_InitClock(...);
while (MCU_PLL_LOCKED != Mcu_GetPllStatus());
Mcu_DistributePllClock();
```

学习方法是把 Configurator 参数、生成的 `Mcu_PBcfg.c`、启动调用和 IAR 寄存器观察连起来。工程中 ECUC 文件和部分旧生成 C 文件时间不同，重新 Generate 前先备份并确认版本。

### 4.2 Port

工程文件：`Config\ECUC\S32K144_Start_Port_ecuc.arxml`

```text
PTE4  = CAN0_RX，输入，CAN0_RX 复用
PTE5  = CAN0_TX，输出，CAN0_TX 复用
PTD0  = FL GPIO 输出
PTD1  = FR GPIO 输出
PTD15 = RL GPIO 输出
PTD16 = RR GPIO 输出
PTB14 = LPSPI1_SCK
PTB15 = LPSPI1_SIN
PTB16 = LPSPI1_SOUT
PTB17 = LPSPI1_PCS3
```

每个 Pin 至少核对 `PortPinId`、`PortPinDirection`、`PortPinMode`、`PortPinInitialMode`、`PortPinLevelValue`、`PortPinPcr`、上下拉和驱动能力。LED 是低电平有效，四路 GPIO 初始值设为高。

### 4.3 Dio 和 IoHwAb

`Config\ECUC\S32K144_Start_Dio_ecuc.arxml` 中：

```text
DioChannel_PTD0  = 0
DioChannel_PTD1  = 1
DioChannel_PTD15 = 15
DioChannel_PTD16 = 16
```

IoHwAb 将抽象操作映射到 DIO：

```text
FL -> PTD0 -> LED2
FR -> PTD1 -> LED3
RL -> PTD15 -> LED4
RR -> PTD16 -> LED5
```

必须区分 `PortPinId` 和 `DioChannelId`；当前数值碰巧相同，不代表概念相同。

### 4.4 Can、CanIf、PduR、Com

当前 CAN 控制器：

```text
FlexCAN0，ControllerId=0，500 kbit/s
CAN clock=80 MHz，Rx/Tx=Interrupt
```

当前实际应用报文：

```text
0x210，DLC=8，接收转向灯输入
0x200，DLC=2，发送左右灯状态
```

数据流：

```text
CAN -> Can -> CanIf -> PduR -> Com -> RTE -> TurnLight
TurnLightAct -> RTE -> Com -> PduR -> CanIf -> Can -> 0x200
```

CanIf 只识别 PDU/ID/DLC；PduR 只转发 PDU；Com 按位偏移和长度解包信号。当前 Com 典型位定义：

```text
HazardSw       bit 8，4 bit
IGN_Status     bit 12，4 bit
Fb_FL          bit 16，4 bit
Fb_FR          bit 20，4 bit
Fb_RL          bit 24，4 bit
Fb_RR          bit 28，4 bit
TurnLampSw     bit 32，4 bit
状态 L         bit 1，4 bit
状态 R         bit 8，4 bit
```

### 4.5 Os/Rte

课件要求 10 ms 诊断和闪烁控制。当前工程的三个主要 Runnable 都是 10 ms：

```text
OS Task -> RTE Timing Event -> TurnLight_Runnable_10ms
OS Task -> RTE Timing Event -> TurnLightArb_Runnable_10ms
OS Task -> RTE Timing Event -> TurnLightAct_Runnable_10ms
```

代码证据位于 `Appl\Source\TurnLight*.c` 和对应的 `Rte_*.h`。`Rte_Read`、`Rte_Write`、`Rte_Call` 是应用访问通信信号和硬件服务的入口。

### 4.6 Spi

当前 LPSPI1 引脚为 PTB14~PTB17。学习时依次确认：Channel、Job、Sequence、数据宽度、波特率、CPOL、CPHA 和 PCS3，然后追踪：

```text
Spi_AsyncTransmit -> Sequence -> Job -> LPSPI1
```

## 5. 课件需求与当前板上实验的对应

| 课件需求 | 当前板上实现 |
|---|---|
| AD 转向开关 | 用 CAN `0x210` 的 `TurnLampSw` 模拟 |
| GPIO 危险开关 | 当前主要通过 CAN 输入模拟 |
| HSD 灯输出 | PTD 四路 LED GPIO |
| 车速、碰撞、紧急制动 | CAN 输入字段/信号模拟 |
| 前灯短路、灯泡开路检测 | 课件有要求，教学板未完整接入真实故障采样 |
| EEPROM `SetFrontDirL` | 课件要求，当前实验重点不是完整 NvM 标定 |
| DTC 当前/历史 | 工程有 Dem 基础，但不能据此宣称已完成全部灯具诊断闭环 |

## 6. 本项目的学习顺序

```text
第1课 Mcu：时钟树和启动调用
第2课 Port：引脚复用、GPIO 初值和 CAN/SPI 管脚
第3课 Dio：通道、低有效 LED 和 IoHwAb 映射
第4课 Can：FlexCAN、波特率、邮箱和中断
第5课 CanIf/PduR/Com：0x210/0x200、PDU、信号位定义
第6课 Os/Rte：10 ms 调度和 Rte API
第7课 Spi：Channel/Job/Sequence 和时序
第8课 Generate/IAR：生成、编译、下载、断点和寄存器验证
```

每一课都执行同一闭环：

```text
看 Configurator 参数 -> 找生成 C -> 找启动/运行时调用 -> IAR 观察 -> 板上验证
```
